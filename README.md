## ECS prototype

This is a very early and unpolished prototype of an ECS library based around the idea of using APT and code generation instead of reflection and multiple layers of abstraction.

Think of this as proof-of-concept or a vision of what could be. Nothing is final, everything is subject to change, including the entire public API.

No license yet, will most likely be Apache 2.0 eventually. I can be found in the #ecs discord channel of [libGDX](https://github.com/libgdx/libgdx).

> [!CAUTION]
> This library produces Java 8 compatible code, but projects using this library must be compiled with JDK 21 or higher.
> If targeting a java version lower than 21, set the source and target to that version, but use a JDK 21 or higher for compilation.

### Getting started

#### Example project

The example project is located in [examples/roguelike](/examples/roguelike) and showcases some of the implemented features.
As there is no documentation yet, this example and the various test cases are the only "documentation" of the functionaly.
See the JavaDoc in the example project and the api module for further details.

To run the example project, execute the following command from a terminal:

```bash
mvn clean install -am -pl codegen -DskipTests && java -jar examples/roguelike/target/decs-examples-roguelike-0.1.0-SNAPSHOT.jar
```

#### Build the library

```bash
mvn clean install
```

#### Maven

```xml
<dependency>
    <groupId>de.schosin.decs</groupId>
    <artifactId>decs-api</artifactId>
    <version>0.1.0-SNAPSHOT</version>
</dependency>
<dependency>
    <groupId>de.schosin.decs</groupId>
    <artifactId>decs-core</artifactId>
    <version>0.1.0-SNAPSHOT</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>de.schosin.decs</groupId>
    <artifactId>decs-codegen</artifactId>
    <version>0.1.0-SNAPSHOT</version>
    <optional>true</optional>
</dependency>
```

> [!NOTE]
> Newer versions might require setting the annotation processor explicitly. <br />
> See [maven-compiler-plugin documentation](https://maven.apache.org/plugins/maven-compiler-plugin/compile-mojo.html#annotationprocessors) for more information.

### Features

#### Current features

- APT-based code generation to produce java 8 compatible code
- Basic ECS operations, such as creating and modifying entities, and creating systems using annotations
- Zero reflection* at runtime

#### Planned features

- Parallel system invocation
- Interface-based components to support optimal* memory layout for primitive fields
- GWT/Android/iOS support
- ...

### Known problems / Missing features

- The JavaDoc in the api module is most likely outdated in multiple places
- Due to how incremental compilation works, the generation of some files has to wait until the processing is over.
This causes compiler warnings by javac in the maven build.
- Annotation processors are not notified when types are removed.
As such the generated code can reference these removed types and require a clean full build to compile.

- No conditional processor execution (enabled/disabled or boolean conditions)
- `IntervalSystem` has to be implemented manually
- `World#createEntitySet` not implemented yet
- Parallel systems (`WorldBuilder#parallel`) not fully implemented and not tested yet

#### Eclipse

Eclipse JDT does not use annotation processors that are opened as an Eclipse project.
Install the project via maven before importing and close the `codegen` module. 
To develop the `codegen` module, open it in another instance of Eclipse or another IDE.

The `values` module should also be closed unless when working on it.
The API of the types in that module are used by the `api` and `core` module, but the final types are generated by the annotation processor.
Eclipse might show incorrect errors if this module is open, as it sometimes favours those types over the generated ones.
